## 二、总体路线

```
阶段                 优先级    状态
─────────────────────────────────────────────────
有声书生成             P0       ✅ 完成
人声提取工具           P0       ✅ 完成（独立工具）
```

**为什么不直接做视频**：当前 12GB 显存的 RTX 3060 跑动漫视频生成（即使是最新的 Index-AniSora V3.1 12GB 版）仍很吃力，5 秒片段需要数分钟。一小时有声书需要几十个镜头，总耗时难以接受。插图生成在硬件需求、生成速度、角色一致性控制上都成熟得多。

**视频生成并非放弃，而是延后**：等消费级显卡达到 24GB+ 显存成为主流，或社区蒸馏出更轻量的模型后，插图生成积累的角色视觉数据可以直接迁移到视频流水线中。

## 三、插画生成方案

### 3.1 设计理念：跟音色克隆一样

有声书的核心体验是"角色说话"。用户可以选择：

| 场景 | 有用户提供参考 | 无用户提供参考 |
|------|---------------|---------------|
| **语音** | 用参考音频克隆角色音色 | 用默认男女音色 |
| **角色外貌** | 用参考画像保持角色长相一致 | 用默认外貌描述 |

**核心原则**：参考是可选的增强，不是必需的。用户不提供任何参考也能跑通，提供了效果更好。

### 3.2 流程图

```
[已有数据]
场景分割结果 (bgm_segments.json)
  ├─ 每段场景的起止时间
  ├─ 场景情感标签（日常/悬疑/战斗/悲伤/浪漫/史诗）
  └─ 场景文本摘要

角色卡 (docs/角色卡.md)
  ├─ 角色名称
  ├─ 角色外貌描述
  └─ 角色性格特征

         ↓

[Prompt 组装]
  "动漫风格，[场景描述]，[角色外貌描述]，[情感氛围]，[镜头描述]"

         ↓

[插图生成]
  ├─ 用户提供角色参考图 → IP-Adapter / 角色 LoRA → 保持长相一致
  └─ 无参考图 → 纯文本 prompt 生成

         ↓

[输出]
  output/illustrations/
  ├── chapter_001/
  │   ├── 000_scene_daily.jpg     # 第0场景：日常对话
  │   ├── 001_scene_battle.jpg    # 第1场景：战斗
  │   └── 002_scene_sad.jpg       # 第2场景：悲伤
  ├── chapter_002/
  │   └── ...
  └── illustration_index.json     # 插画与时间轴的对应关系
```

### 3.3 复用现有数据

| 现有模块 | 插画流水线中如何复用 |
|---------|-------------------|
| `backend/data/bgm_segments.json` | 场景起止时间 → 各插图对应的时间点 |
| `backend/data/bgm_segments.json` 中的情感标签 | 控制插画的情感氛围、色调、构图 |
| `docs/角色卡.md` | 角色外貌描述 → prompt 中的角色描写 |
| `backend/app/core/emotion_labeler.py` | 每段对话的情感标注 → 角色面部表情 |
| `backend/app/core/bgm_generator.py` | 场景分类逻辑 → 插图类型分类可复用 |

### 3.4 技术选型考虑

| 模型 | 优点 | 缺点 |
|------|------|------|
| **SDXL** | 生态成熟、LoRA/IP-Adapter 支持好、动漫模型多 | 不是最新 |
| **FLUX** | 质量更高、构图更好 | 显存需求高（12GB 勉强）、动漫风格LoRA不够丰富 |
| **SD3.5** | 质量介于 SDXL 和 FLUX 之间 | 社区资源不够多 |
| **动漫特化模型（如 Anything/NovelAI 系）** | 动漫风格最佳 | 需要合规确认 |

初步推荐：**SDXL + 动漫 LoRA** 作为起步方案，12GB 显存友好，社区资源丰富。

### 3.5 角色一致性方案

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| **IP-Adapter** | 用参考图直接控制角色长相，无需训练 | ★★★★★ 首推 |
| **角色 LoRA** | 每个角色训练一个 LoRA，需要几张参考图 | ★★★★☆ 效果好但需训练 |
| **纯文本 prompt** | 用户未提供参考图时的回退方案 | ★★★☆☆ 默认 |

### 3.6 输出格式

```
output/illustrations/
├── chapter_001/
│   ├── 000_daily.jpg          # 关键场景插图
│   ├── 001_battle.jpg
│   ├── 002_romantic.jpg
│   └── meta.json              # 该章插图元数据
├── chapter_002/
│   └── ...
└── illustration_index.json    # 全局插图索引

illustration_index.json 结构：
{
  "illustrations": [
    {
      "chapter": 1,
      "scene_index": 0,
      "scene_type": "daily",
      "timestamp_ms": 123450,        // 对应音频时间轴位置
      "image_path": "chapter_001/000_daily.jpg",
      "prompt": "...",
      "characters": ["主角", "配角"],
      "emotion": "轻松"
    },
    ...
  ]
}
```

插图与音频时间轴关联后，听书时可以同步展示对应画面。

## 四、视频生成（延后）

### 4.1 何时重启

1. **硬件条件满足**：消费级显卡达到 24GB+ 显存（RTX 5070/6070 系列）
2. **模型轻量化完成**：社区蒸馏出 8-12GB 可用的高质量动漫视频模型
3. **插图数据积累足够**：通过插画生成积累了角色视觉数据、场景构图偏好

### 4.2 从插图到视频的路径

```
插图阶段积累的资产：
  ├─ 角色参考图 / 角色 LoRA
  ├─ 场景构图偏好（prompt 模式）
  ├─ 时间轴 - 场景对照数据
  └─ 用户反馈数据（哪些插图效果好）

         ↓

视频阶段直接迁移：
  ├─ 角色 LoRA → 视频模型 LoRA
  ├─ 场景 prompt → 视频 prompt
  ├─ 时间轴 → 视频分镜
  └─ 插图 → 视频关键帧（图生视频 I2V）
```

插图不是白白过渡，而是为视频生成积累核心资产。

### 4.3 候选视频项目（持续关注）

| 项目 | 关注理由 | 当前状态 |
|------|---------|---------|
| **Index-AniSora V3 系列** | B 站出品，动漫特化，Apache 2.0 | 已有 12GB 版，仍需观望 |
| **AnimeLoom** | 角色 face lock 方案好 | 显存需求高 |
| **CogVideoX** | 5B 轻量，文档好 | 非动漫特化 |
| **社区蒸馏模型** | 未来可能出现 8-12GB 版本 | 待观察 |
