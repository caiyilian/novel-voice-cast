# Novel Voice Cast 全流程使用教程

本文说明如何仅使用一份小说原文 `novel.txt` 和一份对话说话人标注 `labels.txt`，完成：

> 解析 → 性别识别 → 情绪标注 → 逐句表演导演 → VoxCPM 音色克隆 → 全书语音拼接 → BGM 场景分割/标注/生成/混音 → 视觉规划/审核 → MiniMax H3 原生链式镜头 → 中文字幕 → 横竖版视频

最后还介绍两个不属于主流程的可选后处理功能：

1. 把横竖版成片自然拆成多个严格小于指定时长的视频；
2. 只更换某一个角色的克隆参考音频，复用其余全部缓存并生成独立的新版本。

本文所有命令均假设在 Windows CMD 中运行，项目目录为：

```text
E:\projects\novel-voice-cast
```

## 2. 准备输入文件

### 2.1 `novel.txt`

小说必须保存为 UTF-8 文本，默认位置：

```text
novels/novel.txt
```

推荐保留：

- 原有自然段和空行；
- `第一章`、`第二幕`、`终章`、`后记` 等章节标题；
- 中文对话引号，例如 `「……」`；
- 旁白、动作和环境描写。

简化示例：

```text
第一幕

风吹过麦田，金色麦穗一层层伏倒。
「今晚就在这里休息吧。」
「咱可不想睡在漏风的马车里。」
罗伦斯无奈地叹了口气。
```

### 2.2 `labels.txt`

默认位置：

```text
novels/labels.txt
```

`labels.txt` 的规则是：

- 每一条被解析出的对话对应一行角色名；
- 顺序必须与 `novel.txt` 中的对话顺序完全一致；
- 旁白行不写入 `labels.txt`，程序会自动把非对话叙述作为旁白；
- 同一个人物连续说多句，也要重复写多行角色名；
- 不要增加说明文字、序号或空行。

与上面的小说示例对应：

```text
罗伦斯
赫萝
```

当前示例小说有 1349 条显式对话标签，解析后旁白和对话合计为 3026 个 TTS 片段。

### 2.3 先验证解析

只运行解析阶段不会调用模型，也不会生成语音：

```cmd
cd /d E:\projects\novel-voice-cast
set "PYTHONUTF8=1"
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --from-stage parse --to-stage parse --log logs\parse_check.log
```

控制台会输出类似：

```text
parsed 3026 dialogues and 24 characters
```

如果角色或对话数明显不对，应先修正 `novel.txt` 和 `labels.txt`，不要直接开始数天的长流程。

## 3. Python、FFmpeg 与本地模型环境

### 3.1 项目 Python 环境

项目已经有 `.venv` 时无需重复创建。新环境可以执行：

```cmd
cd /d E:\projects\novel-voice-cast
py -3.11 -m venv .venv

.venv\Scripts\python.exe -m pip install -r requirements_full.txt
```

### 3.2 FFmpeg

需要完整 FFmpeg，并且视频字幕烧录必须支持 `libass/subtitles` 滤镜。当前配置为：

```yaml
video:
  ffmpeg: "D:/ffmpeg-7.1.1-full_build/bin/ffmpeg.exe"
  ffprobe: "D:/ffmpeg-7.1.1-full_build/bin/ffprobe.exe"
```

如果安装位置不同，修改这两个路径。可以检查：

```cmd
D:\ffmpeg-7.1.1-full_build\bin\ffmpeg.exe -version
D:\ffmpeg-7.1.1-full_build\bin\ffmpeg.exe -filters | findstr subtitles
```

### 3.3 VoxCPM 环境

所有旁白、主角和路人都强制使用 VoxCPM 音色克隆，不使用 Edge-TTS 代替：

```yaml
clone_engine: "voxcpm"

voxcpm:
  force_all_characters: true
  model_path: "backend/models/VoxCPM2"
  module_path: "E:/projects/音色克隆/VoxCPM"
  python: "E:/projects/音色克隆/VoxCPM/.venv/python.exe"
```

需要确认：

1. `model_path` 中存在 VoxCPM2 模型权重；
2. `module_path` 是可导入 VoxCPM 源码的目录；
3. `python` 是已经安装 VoxCPM 依赖的独立 Python；
4. 该环境能使用 NVIDIA GPU。

本项目会按语义标点拆分长句、逐块生成并质检，失败时重新随机采样；不会用 FFmpeg 拉伸或减慢人物语音。

## 4. 大模型和生成模型配置

### 4.1 SenseNova 文本模型与 API Key

下列阶段使用 SenseNova：

| 阶段 | 模型 |
|---|---|
| 性别识别 | `sensenova-6.7-flash-lite` |
| 情绪标注 | `sensenova-6.7-flash-lite` |
| 角色表演档案与逐句表演导演 | `sensenova-6.7-flash-lite` |
| BGM 场景分割和类型/提示词标注 | `sensenova-6.7-flash-lite` |
| 插图提示词审核 | `sensenova-6.7-flash-lite` |
| 插图规划 | 默认 `deepseek-v4-flash`，必要时可使用 Agnes 文本模型回退 |

Key 文件：

```text
config/sensenova_apikeys
```

每行放一个完整 API Key，例如：

```text
key_account_1
key_account_2
key_account_3
```

规则：

- 可以放任意数量的账号，不需要在代码中填写账号数；
- 程序启动时读取所有非空行；
- 多账号自动轮询；
- 某个账号限流、配额不足或临时失败时会进入冷却并切换账号；
- 新增第 7 行后，下次启动会自动按 7 个账号轮询；
- 不要把 Key 提交到 Git。

严格的 Issue #99 阶段不会偷偷切换为其他模型；所有 SenseNova 账号都暂时不可用时会等待最早恢复的账号。

当前核心配置：

```yaml
llm:
  provider: "sensenova"
  model: "sensenova-6.7-flash-lite"
  rate_limit_cooldown_seconds: 15
```

### 4.2 角色参考音频

显式配置的角色优先使用自己的参考音频；其他角色按性别使用默认参考音频：

```yaml
characters:
  "旁白": "backend/data/presets/design_male_deep.wav"
  "罗伦斯": "backend/data/presets/demo_male.mp3"
  "劳伦斯": "backend/data/presets/demo_male.mp3"
  "赫萝": "backend/data/presets/holo_speech_only.wav"

default_audio:
  male: "backend/data/presets/design_elderly.wav"
  female: "backend/data/presets/reference_speaker.wav"
```

参考音频应满足：

- 只有一个人说话；
- 无 BGM、无混响、无明显噪声；
- 音量稳定；
- 内容清楚，尽量包含自然语气变化；
- 路径可由 VoxCPM 的独立 Python 访问。

只替换一个角色的参考音频不需要重做性别、情绪和表演导演。本文第 11 节提供独立脚本。

### 4.3 ACE-Step 本地 BGM

BGM 由项目内的 ACE-Step 1.5 本地生成：

```yaml
bgm:
  enabled: true
  model: "acestep-v15-turbo"
  lm_model: "acestep-5Hz-lm-1.7B"
  thinking: false
  cpu_offload: false
  clips_per_segment: 3
  clip_duration: 60
  inference_steps: 8
  proxy: "http://127.0.0.1:7890"
```

当前使用经验证能正常成曲的纯 DiT 路径，`thinking: false`。`proxy` 主要用于首次下载模型权重；模型已在本地缓存后不需要持续联网。

BGM 阶段默认使用独立环境：

```text
ACE-Step-1.5/.venv/Scripts/python.exe
```

如果 ACE-Step 环境放在其他位置，在 `bgm` 中增加或修改：

```yaml
python: "E:/your-path/ACE-Step-1.5/.venv/Scripts/python.exe"
```

该环境需要能够正常导入项目内 `ACE-Step-1.5/acestep`、PyTorch 和音频依赖，并能识别 NVIDIA GPU。

如果没有 7890 代理，模型已经下载完成时可以删除或修改该字段；首次下载仍需提供可用网络。

### 4.4 文生图服务

当前使用独立服务器上的本地 HTTP 文生图接口，不使用 Agnes 生图额度：

```yaml
illustrations:
  provider: "local-http"
  endpoint: "http://172.31.102.189:8000/generate"
  model: "local-image"
  size: "896x1152"
  steps: 25
  cfg: 7.0
  seed: -1
```

接口要求：

- `POST /generate`；
- 表单字段支持 `prompt`、`neg_prompt`、`steps`、`cfg`、`height`、`width`、`seed`；
- 成功时响应体直接返回 PNG；
- 项目机器必须能够访问配置中的 IP 和端口。

横屏同时启用：

```yaml
illustrations:
  landscape:
    enabled: true
    size: "1280x720"
```

运行前可以用项目 Python测试接口：

```cmd
.venv\Scripts\python.exe E:\projects\GRUMon\test.py
```

如果生图服务部署在当前电脑，可把 endpoint 改为：

```yaml
endpoint: "http://127.0.0.1:8000/generate"
```

如果改用 Agnes，将 `provider` 改为 `agnes`，并在 `config/agnes_api_key` 中保存 Key；默认 Agnes 网络代理为 `http://127.0.0.1:7890`。

### 4.5 MiniMax H3 视频服务

默认视频阶段不再逐张使用旧插图作为首尾帧，而是每个 BGM 粗场景先以 T2VA 建立新画面，再用上一条 H3 的续帧进行 I2VA。配置与接口详见 [`MiniMax-H3视频集成.md`](MiniMax-H3视频集成.md)。服务地址：

```yaml
video:
  h3:
    enabled: true
    mode: "native-chain"
    endpoint: "http://172.31.102.189:8189"
```

已有全部前置产物时，可只运行视频阶段：


## 6. 一条命令运行完整流程

推荐在前台 CMD 运行：

```cmd
cd /d E:\projects\novel-voice-cast
set "PYTHONUTF8=1"
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --stream-tts --log logs\run_full.log
```

`--stream-tts` 会让已经完成表演指导的台词立即进入 TTS：

- performance 继续独立向前生成；
- TTS 只消费已经完成的 performance；
- TTS 追上后等待新结果；
- TTS 不会阻塞 performance；
- performance 完成后，主流程等待 TTS 补齐，再进入拼接。

当前配置中的 `streaming_tts.enabled: true` 已默认启用该能力，命令保留 `--stream-tts` 是为了让意图更明确。

如果希望把所有控制台输出另外保存一份，可在 CMD 使用：

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --stream-tts --log logs\run_full.log 2>&1 | powershell -NoProfile -Command "$input | Tee-Object -FilePath 'logs\run_full_console.log'"
```

## 7. 13 个主流程阶段

| 序号 | 阶段名 | 作用 | 是否可断点 |
|---:|---|---|---|
| 1 | `parse` | 解析旁白、对话、章节和说话人 | 重新执行很快 |
| 2 | `gender` | 根据全文证据识别角色性别 | 是 |
| 3 | `emotion` | 逐句标注情绪和语气 | 是 |
| 4 | `performance` | 建立角色档案并生成逐句自然语言表演指导 | 是 |
| 5 | `tts` | 所有句子使用 VoxCPM 克隆音色并生成 WAV | 是，细到语义短块 |
| 6 | `splice` | 按原顺序拼成无 BGM 完整语音 | 可重建 |
| 7 | `bgm-segment` | 把小说划分为音乐场景 | 是 |
| 8 | `bgm-label` | 给场景生成类型、速度、能量、音乐提示词 | 是 |
| 9 | `bgm-generate` | ACE-Step 为每个场景生成多条本地 BGM | 是，逐曲保存 |
| 10 | `bgm-mix` | 按新语音时间轴混入 BGM | 可重建 |
| 11 | `illustration-plan` | 规划全书插图及视觉提示词 | 是 |
| 12 | `illustrations` | 提示词审核并异步生成横竖插图 | 是，逐图保存 |
| 13 | `video` | 逐条生成/续写 H3 镜头，按真实 WAV 时长编码字幕和横竖视频 | 是，远程任务、视频片段和本地编码均有断点 |

## 8. 出错、停止和断点续跑

### 8.1 判断是否成功

成功结束时会看到：

```text
Pipeline complete ...
Run manifest: ...\output\run_full_manifest.json
```

失败时会看到：

```text
PIPELINE FAILED: ...
```

`PIPELINE FAILED` 不是正常结束。已经成功的 checkpoint 会保留。

### 8.2 断点续跑

最安全的恢复方式通常是重新执行完全相同的完整命令：

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --stream-tts --log logs\run_full.log
```

程序会核对模型版本、小说哈希、配置、参考音频哈希和输出文件，不是单纯“看到文件就跳过”。兼容的成功项复用，不兼容项自动重做。

也可以从某阶段继续，例如：

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --from-stage performance --log logs\resume_performance.log
```

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --from-stage tts --to-stage bgm-mix --log logs\resume_audio.log
```

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --from-stage illustrations --to-stage video --log logs\resume_video.log
```

若视觉提示词审核已完成，不需要重新跑插图阶段，可直接使用：

```cmd
.venv\Scripts\python.exe -u scripts\run_full.py --config config\config.yaml --from-stage video --to-stage video --log logs\h3_video.log
```

只有在前置阶段缓存已经完整时，才应使用 `--from-stage`。不确定时先加 `--dry-run`。

### 8.3 Ctrl+C

可以在前台按 `Ctrl+C` 停止。主流程会记录 interrupted 状态，已原子写入的模型结果、WAV、BGM 和图片不会丢失。再次执行相同命令继续。

不要直接删除 checkpoint 来“修复”模型格式错误；应先修代码或配置，再利用已有断点继续。

## 10. 可选后处理：自然拆成小于指定时长的视频

这不是 13 阶段主流程的一部分。只有最终横竖视频生成完成后才运行。

默认把当前横竖成片拆成严格小于 60 分钟、并保留 30 秒安全余量的多个视频：

```cmd
cd /d E:\projects\novel-voice-cast
set "PYTHONUTF8=1"
.venv\Scripts\python.exe -u scripts\split_video_parts.py --max-minutes 60 --safety-seconds 30
```

默认输出：

```text
output/video_parts_under_60min/
├─ portrait/
├─ landscape/
├─ split_manifest.json
└─ 分段清单.txt
```

脚本不会在第 60 分钟机械切断，而会综合：

- 完整 TTS 语句交界；
- 章节/幕/终章/后记标题；
- 大模型生成的 BGM 场景边界；
- 大模型生成的插图场景边界；
- 横竖版共同关键帧。

使用 FFmpeg `-c copy` 无损拆分，不重新压制母版。已有分段需要覆盖时增加 `--force`。

例如平台限制 30 分钟：

```cmd
.venv\Scripts\python.exe -u scripts\split_video_parts.py --max-minutes 30 --safety-seconds 20 --output-dir output\video_parts_under_30min
```

处理任意文件时可重复传入 `--input 名称=路径`：

```cmd
.venv\Scripts\python.exe -u scripts\split_video_parts.py ^
  --input "横屏=output\my_landscape.mp4" ^
  --input "竖屏=output\my_portrait.mp4" ^
  --novel novels\novel.txt ^
  --labels novels\labels.txt ^
  --segments-dir output\segments ^
  --illustration-plan output\illustration_plan.json ^
  --bgm-segments backend\data\bgm_segments.json ^
  --output-dir output\my_video_parts ^
  --max-minutes 60
```

## 11. 可选后处理：只把赫萝换成新的克隆音色

当前标准配置中赫萝使用：

```text
backend/data/presets/holo_speech_only.wav
```

希望比较的新参考音频是：

```text
backend/data/presets/design_female_gentle.wav
```

如果是从零开始的新书，只需要把 `config/config.yaml` 中这一行改掉：

```yaml
"赫萝": "backend/data/presets/design_female_gentle.wav"
```

但当前第一卷已经全部生成完，直接改配置再运行会使赫萝 TTS 指纹失效，而且新的赫萝语音总时长会改变后续时间轴。为保留现有母版，使用独立脚本：

```text
scripts/rebuild_speaker_voice.py
```

它是通用脚本，默认参数正好是“赫萝 → design_female_gentle.wav”。处理范围：

- 复用解析、性别、情绪和 performance；
- 复用其他角色全部 WAV；
- 只重新生成目标角色的 VoxCPM WAV；
- 复用已经生成的 BGM 曲目，只按新时间轴重新混音；
- 复用全部横竖插图；
- 重新生成 SRT、横竖版视频；
- 最后自动生成小于 60 分钟的横竖分段；
- 所有新产物放进独立目录，不修改原成片。

## 12. 修改配置后哪些阶段需要重跑

| 修改内容 | 最早需要重跑的阶段 |
|---|---|
| 小说原文或 labels | `parse`，通常建议完整流程 |
| 角色性别模型逻辑 | `gender` |
| 情绪规则/模型 | `emotion` |
| performance 提示词/规则 | `performance` |
| 某角色参考音频 | 该角色 `tts`；再重建 splice、bgm-mix、video |
| VoxCPM 采样参数或代码 | `tts` |
| BGM 场景划分参数 | `bgm-segment` |
| BGM 音乐提示词/标签 | `bgm-label` |
| ACE-Step 生成参数 | `bgm-generate` |
| BGM 音量 | `bgm-mix` |
| 插图规划 | `illustration-plan` |
| 生图尺寸/提示词/模型 | `illustrations` |
| H3 模式、时长、生成分辨率、服务地址 | `video`（H3 checkpoint 指纹不兼容的镜头会重做） |
| 字体、字号、CRF、最终视频分辨率 | `video`（通常只需重做本地编码） |
| 视频平台时长限制 | 仅运行可选 `split_video_parts.py` |

## 13. 使用原则

1. 长流程优先让 checkpoint 自己恢复，不要随意删除缓存。
2. 修改小说、模型、参考音频或关键参数后，程序会用哈希判断缓存兼容性。
3. `PIPELINE FAILED` 表示错误，不是正常完成；修复原因后执行相同命令继续。
4. VoxCPM、ACE-Step 和视频编码都可能长时间占用 GPU，不要同时启动多个重型实例。
5. 本地文生图可以与提示词审核异步进行；追上审核进度时会等待新提示词。
6. 最终发布前，建议抽听无 BGM 和带 BGM 音频，并抽查横竖视频的字幕、人物音色、插图和章节切点。
7. `config/sensenova_apikeys`、`config/agnes_api_key` 等密钥文件不能提交或分享。
