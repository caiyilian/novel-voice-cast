# 开源动画视频生成项目调研

> 调研日期：2026-06-30
> 目标：为 "Novel Voice Cast" 项目寻找可扩展的动画视频生成方案，实现"小说→有声动画"流水线

---

## 调研背景

现有项目已完成：
```
小说文本 → 角色识别 → 情感标注 → TTS合成 → 拼接 → BGM混音 → 输出有声书
```

下一步扩展目标：**从有声书升级为有声动画**，要求：
1. 输入：小说文本 + 角色长相参考图（可选）
2. 根据文本自动生成动画视频，角色在画面中保持长相一致
3. 角色语音使用现有 VoxCPM 音色克隆（用户提供音频则克隆，否则用默认音色）
4. BGM 流水线复用现有模块

## 一、重点项目详述

### 1.1 AnimeLoom（强烈推荐 ★★★★★）

> GitHub: https://github.com/JoelJohnsonThomas/AnimeLoom  
> 授权：开源  
> 更新：2026-03

**一句话**：文本故事 → 角色一致动画，单 GPU 可跑。

**核心能力**

AnimeLoom 是一个多阶段流水线，将一段文本提示词转化为流畅的动画序列：

1. **故事分解**（Story Decomposition）— Gemini Flash 将一段故事文本拆分为多个镜头描述
2. **角色身份锁定关键帧**（Identity-Locked Keyframes）— SDXL + LoRA + IP-Adapter 生成每个镜头的关键帧，确保角色长相一致
3. **运动合成**（Motion Synthesis）— Wan2.2-I2V-A14B（MoE）将关键帧驱动为动画
4. **人脸锁定**（Face Lock）— 基于 Wan-Animate（arXiv 2509.14055）解耦骨骼运动与面部表情：驱动片段提供动作，关键帧提供人脸参考，输出每一帧都是关键帧的人脸 + 驱动片段的动作
5. **人脸修复**（Face Restoration）— 隔帧 GFPGAN 修复面部细节，防止身份漂移
6. **帧插值**（RIFE）— 16fps → 24fps
7. **放大**（Real-ESRGAN）— 480p → 720p+

**身份一致性演进**

| 版本 | 方案 | 身份一致性 |
|------|------|-----------|
| v1.0 | 无面部处理 | ~70% |
| v1.5 | GFPGAN 逐帧修复 | ~85% |
| v2.0 | Wan2.2-Animate face lock | **~95%+** |

**硬件要求**

| 组件 | 方案 | 显存 |
|------|------|------|
| 关键帧生成 | SDXL + LoRA + IP-Adapter | ~8GB |
| 视频模型 | Wan2.2-Animate-14B | ~46GB 峰值 |
| 人脸修复 | GFPGAN v1.4 | ~3GB |
| 帧插值 | RIFE 4.x | ~6GB |
| 放大 | Real-ESRGAN | ~6GB |

> 注意：46GB 峰值显存需要 A100/4090 等高端显卡。社区已出 LoRA 量化方案可降至 24GB 左右。

**与现有项目的结合点**

- 角色卡：项目的 `docs/角色卡.md` 已有角色描述数据，可直接作为 SDXL 角色 LoRA 的输入
- 语音：VoxCPM 音色克隆 + 情感标注可直接为动画角色配音
- BGM：现有 BGM 流水线可直接对接动画的时间轴

### 1.2 Bilibili Index-AniSora V3（强烈推荐 ★★★★★）

> GitHub: https://github.com/bilibili/Index-anisora  
> 授权：Apache 2.0  
> 论文：https://arxiv.org/abs/2412.10255  
> 更新：2025-08

**一句话**：目前最强大的开源动漫视频生成模型，B 站出品。

**核心能力**

- **纯动漫领域**：10M+ 高质量动漫数据训练，在 VBench 和人工盲测中动漫视频生成达到 SOTA
- **多风格支持**：动画番剧、国产原创、漫画改编、VTuber、动漫 PV、鬼畜动画等
- **角色 3D 旋转视频**：一张正面角色图 → 生成 360° 旋转视频 → 多角度一致建模

**V3 版本新特性**

- 权重 Apache 2.0，公开发布在 ModelScope 和 Hugging Face
- 任意帧推理（arbitrary-frame inference）
- 角色 3D 视频生成
- 视频风格迁移
- 多模态引导
- 超低分辨率视频超分
- 生成速度：5 秒 360p 在 8 秒内完成

**模型结构**

- 数据流水线：10M+ 高质量动漫数据
- 可控生成：时空遮罩模块（spatiotemporal mask module）
  - 图生视频（image-to-video）
  - 帧插值（frame interpolation）
  - 局部图像引导动画
- 评估基准：948 个动漫视频的评估数据集

**与现有项目的结合点**

- AniSora 的图生视频能力最适合：**先用 SDXL/角色 LoRA 生成角色关键帧，再用 AniSora 驱动成动画**
- B 站的中国团队，中文文档和支持更好

### 1.3 JoyAI-Echo（京东开源 ★★★★☆）

> GitHub: https://github.com/jd-opensource/joyai-echo  
> 更新：2026-06

**一句话**：长视频生成 + 音画一致性记忆，5 分钟级别。

**核心能力**

- **跨模态音视频记忆库**（Cross-modal Memory Bank）：保持角色外观和声音音色在 5 分钟视频内一致
- **联合音视频生成**：单流水线输出同步视频和音频
- **DMD 蒸馏**：7.5× 推理加速
- **分钟级多镜头故事**：一个 prompt JSON 生成连续镜头
- **ComfyUI 支持**：[ComfyUI_JoyAI_Echo](https://github.com/zhuang2002/ComfyUI_JoyAI_Echo)

**性能指标（对比 HappyOyster）**

| 维度 | JoyAI-Echo | 平局 | HappyOyster |
|------|-----------|------|-------------|
| 视觉质量 | **63.6%** | 8.8% | 27.6% |
| 音频质量 | **81.7%** | 6.5% | 11.8% |
| 指令遵循 | **80.6%** | 13.5% | 5.9% |
| 角色一致性 | **59.4%** | 12.9% | 27.7% |

**不足之处**

- 当前仅支持 T2V（文生视频），图生视频（I2V）尚未发布
- 显存需求较高（48GB 左右）
- 权重尚未完全开源

**与现有项目的结合点**

- **跨模态记忆库天然适合本项目**：将现有的角色卡 + 音色克隆 + BGM 作为 memory bank 的输入
- 5 分钟连续视频输出，适合小说章节级别

### 1.4 HunyuanVideo-Avatar（腾讯 ★★★★☆）

> GitHub: https://github.com/Tencent-Hunyuan/HunyuanVideo-Avatar  
> 更新：2025-05

**一句话**：音频驱动角色动画 + 情感控制 + 多角色对话。

**核心能力**

- **音频驱动**：输入任意风格的角色图 + 音频 → 输出角色说话动画
- **情感控制**：Audio Emotion Module（AEM）从参考图提取情感，控制角色表情
- **多角色场景**：Face-Aware Audio Adapter（FAA）实现多角色独立音频驱动
- **多风格支持**：写实、卡通、3D 渲染、拟人化角色
- **低显存模式**：结合 Wan2GP 可降至 10GB

**技术架构**

- 基于 MM-DiT（多模态扩散 Transformer）
- 角色图像注入模块：替代传统的加性条件方案，消除训练/推理条件不匹配
- 支持人像、上半身、全身多种画幅

**与现有项目的结合点**

- **最直接的语音驱动方案**：VoxCPM 合成音频 → HunyuanVideo-Avatar 驱动角色动画
- 情感标注数据（已有）可直接传入 AEM 模块
- 适合对话密集的小说场景

## 二、备选流水线方案

### 方案 A：AnimeLoom 路线（推荐）

```
小说文本
  ↓
故事分解（LLM 分镜）
  ↓
角色关键帧生成（SDXL + 角色 LoRA）← 复用 docs/角色卡.md
  ↓
Wan2.2-Animate 驱动动画（Face Lock 保持长相一致）
  ↓
VoxCPM 语音合成 ← 复用现有模块
  ↓
BGM 混音 ← 复用现有模块
  ↓
帧插值 + 超分
  ↓
输出有声动画
```

**优点**：开源、完全本地、角色一致性 95%+
**缺点**：显存需求高（峰值 46GB）

### 方案 B：AniSora + 语音管线

```
小说文本
  ↓
图生视频关键帧（角色 LoRA 生成）
  ↓
AniSora V3 动画生成
  ↓
VoxCPM + BGM 音轨合成
  ↓
ffmpeg 音视频合成
  ↓
输出
```

**优点**：动漫质量最高、B 站出品中文支持好
**缺点**：角色一致性不如 face lock 方案

### 方案 C：JoyAI-Echo 路线

```
小说文本（多镜头 JSON）
  ↓
JoyAI-Echo 跨模态记忆 → 长视频 + 同步音频
  ↓
VoxCPM 替换默认配音 ← 用我们的音色克隆覆盖
  ↓
BGM 叠加
  ↓
输出
```

**优点**：长视频（5 分钟）、音画同步好
**缺点**：权重未完全开源、显存高

## 三、与现有项目的结合点

| 现有模块 | 动画流水线中如何复用 |
|---------|-------------------|
| `docs/角色卡.md` | 角色外貌描述 → SDXL LoRA / IP-Adapter 训练 |
| `backend/app/core/vocal_separator.py` | 人声提取 → 训练角色 LoRA 的参考音频 |
| `backend/app/core/emotion_labeler.py` | 情感标注 → 控制角色表情/语气 |
| `backend/app/tts/voice_clone.py` (VoxCPM) | 角色配音 |
| `backend/app/core/bgm_mixer.py` | 动画 BGM 配乐 |
| `backend/data/bgm_segments.json` | 章节情感/场景标记 → 动画分镜参考 |
