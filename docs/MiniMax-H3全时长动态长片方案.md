# MiniMax H3 全时长动态长片方案

## 1. 背景与现状

当前 H3 `native-chain` 流程按照 702 个插图规划项生成动态镜头：每个粗场景的第一条使用 T2VA，同场景后续镜头使用上一条 H3 视频的末帧作为 I2VA 首帧。该方案解决了静态插图幻灯片的问题，但每个规划项仍然只有一条约 5～10 秒的视频。

小说第一卷最终音频长约 21,666 秒，而竖屏 702 条 H3 视频实际可用动态时长只有约 6,834 秒。现有合成器会在动态视频结束后保持最后一帧直到下一个规划项开始，造成约 14,831 秒静止画面，约占全片 68.5%。702 个规划区间中有 680 个存在尾帧等待，最长一次约 144 秒。

因此，单纯完成现有横竖屏 702 条镜头并不能得到真正持续运动的六小时视频。

## 2. 目标

本方案的目标是生成一部音频、字幕、剧情和镜头严格同步的长片：

- 全片每个时间区间都有动态画面，不使用尾帧静止补时；
- 保留自然的影视切镜，不追求不合理的“六小时一镜到底”；
- 角色外貌、服装、场景、道具和色彩在场景内保持一致；
- 镜头动作服务于小说内容，而不是重复无意义的摇镜、眨眼或衣摆运动；
- 竖屏和横屏共享同一份语义分镜与资产设定，同时各自使用适合画幅的构图；
- 所有远程任务、下载、质量检查和本地渲染均可断点继续；
- 现有 H3 片段只作为候选素材复用，新流程不删除或覆盖旧成片。

## 3. 不采用的方案

### 3.1 延长最后一帧

这是当前问题的直接来源，新流程必须禁止使用静止帧填补时间缺口。

### 3.2 循环或正反播放短视频

虽然成本低，但会出现重复动作、人物来回移动和明显的时间倒流，不符合长片质量要求。

### 3.3 仅使用光流插帧或慢放

插帧只能提高已有运动的帧率，不能创造新的动作。大幅慢放还会产生橡皮感、变形和不自然节奏。

### 3.4 无限尾帧续写

连续把上一条末帧传给下一条，能够获得运动，但误差会逐段累积，最终出现人物变脸、服装变化、场景结构漂移和坏帧传播。它只能作为短镜头链的局部手段，不能贯穿整部影片。

## 4. 推荐架构

### 4.1 音频锁定的微分镜规划

以 `full_volume_bgm.mp3` 和已经验证的对白时间轴为唯一时间基准，将 702 个粗规划区间进一步拆成约 5～10 秒的微镜头。每条微镜头至少包含：

- 精确的开始、结束时间和目标帧数；
- 对应小说原文、说话人、情绪和表演方向；
- 场景、在场角色、服装、道具和空间关系；
- 景别、构图、镜头运动、人物动作及最终状态；
- 与前后镜头的关系：连续镜头、反应镜头、视角切换或场景切换；
- 竖屏与横屏各自的构图说明；
- 可审计的原文证据和生成提示词。

分镜数量由实际时间轴计算，不硬编码为 2,487 条。当前数据按最长约 10.125 秒估算，每个方向约需 2,487 条。

### 4.2 角色、场景和道具资产圣经

建立可复用的视觉资产描述：

- 主要角色：正面、四分之三侧面、全身、表情、发型、年龄、体型和固定服装；
- 场景：空间布局、时间、天气、光线、主色调和固定陈设；
- 道具：马车、钱袋、武器、商品等外观与相对尺寸；
- 连续性状态：角色当前是否受伤、衣服是否湿润、道具在谁手中等。

每个镜头只读取所需资产，避免提示词无限膨胀。场景状态变化必须由分镜显式记录，不能让模型自行猜测。

### 4.3 关键帧锚定与有限镜头链

生成策略按优先级选择：

1. **FL2VA 首尾帧约束**：重要动作和角色特写同时提供准确的首帧与尾帧，提示词描述两帧之间的物理运动路径。
2. **I2VA 短链续写**：同一构图中的连续动作可使用上一条末帧，但链长应有限；达到阈值或检测到漂移后必须用新关键帧重新锚定。
3. **T2VA 场景重置**：新地点、新时间段或有意硬切时，以完整资产描述重新建立镜头。
4. **L2VA 收束**：需要精确落到某个剧情关键画面时，可从目标尾帧反推合理开场。

切镜本身不是缺陷。专业长片应在叙事节点使用远景、中景、近景、反应镜头和有意硬切；目标是每一秒都有合理运动，而不是整部影片只有一条连续镜头。

### 4.4 自动质量门禁

每条视频下载后必须经过本地质量检查，未通过时更换随机种子重试：

- 分辨率、帧率、时长、解码和文件完整性；
- 黑帧、纯色帧、重复帧和长时间近乎静止；
- 首帧及尾帧与目标关键帧的相似度；
- 人脸、服装、道具和场景连续性；
- 闪烁、畸形肢体、异常镜头跳变和文字水印；
- 动作是否与当前分镜及原文一致。

自动检查不能确定时标记为 `review_required`，不能静默进入最终成片。失败记录、随机种子、远程任务号和审核理由全部写入断点。

### 4.5 无静止补齐的精确合成

每个粗规划区间由多条微镜头覆盖。合成前执行逐帧覆盖校验：

- 动态素材覆盖范围必须达到区间结束帧；
- 相邻镜头只能使用硬切或明确配置的短转场；
- 最后一条可裁剪到精确帧数，但不能延长最后一帧；
- 任意一帧存在覆盖缺口时，最终合成必须失败并报告缺口；
- H3 自带音轨不进入成片，继续使用 VoxCPM 配音、既有 BGM 和字幕；
- 最终视频时长与母音频误差不得超过 0.25 秒。

## 5. 断点与目录设计

建议新增以下版本化文件，避免破坏旧版数据：

```text
backend/data/h3_shot_plan.json
backend/data/h3_shot_plan.checkpoint.json
output/h3_video_continuous/
  portrait/
    keyframes/
    clips/
    continuation_frames/
    render_segments/
    h3_coverage.checkpoint.json
    h3_render.checkpoint.json
  landscape/
    ...
```

镜头断点至少保存：静态身份哈希、画幅、分镜版本、提示词哈希、首尾帧哈希、随机种子、远程 `job_id`、尝试次数、质量指标、输出哈希及前后镜头依赖。

程序重启后遵循以下规则：

- 完整且哈希匹配的视频直接复用；
- 远程任务仍存在时继续轮询，不重复提交；
- 服务器重启导致任务 404 时只重提当前镜头；
- 输入或分镜变化时仅失效受影响镜头及其短链后继；
- 不因为一个早期镜头变化而无条件清空整个六小时缓存。

## 6. 旧素材迁移

- 旧竖屏 702 条和横屏已完成片段保持原位，不删除；
- 对旧片段执行相同质量门禁，并检查其内容是否匹配新微分镜；
- 通过检查的旧片段可作为区间第一条或独立镜头复用；
- 不匹配或漂移严重的片段保留但不进入新成片；
- 旧竖屏最终视频作为可回退版本，新版本输出到独立文件名。

截至 2026-09-01 暂停旧流程时，横屏断点已有 72 条成功，第 73 条远程任务已经提交。该任务结果可在新流程迁移阶段尝试回收。

## 7. 横竖屏策略

两种画幅共享同一份剧情、时间和镜头语义，但不简单裁切：

- 横屏以环境、双人关系和运动方向为重点；
- 竖屏以人物、表情和纵深层次为重点；
- 两者共享角色与场景资产、镜头编号和首尾状态；
- 每个画幅单独生成关键帧和视频，以避免主体被裁掉或字幕遮挡；
- 同一镜头的两个画幅必须通过一致性检查。

## 8. 成本预估

当前音频约 21,666 秒。若平均每条覆盖 8～10 秒，每个方向约需 2,500～2,900 条视频。按当前服务器约 5 分钟一条估算，在复用已有素材后，横竖屏仍可能连续运行约 15 天；考虑质量重试和服务中断，实际可能需要 2～3 周。

该时间成本符合本项目“质量优先、允许长时间运行”的原则，但必须依靠完整断点、远程任务恢复和质量门禁避免浪费。

## 9. 验收标准

新方案完成时必须同时满足：

1. 横竖屏所有时间区间动态覆盖率为 100%；
2. 渲染器不存在尾帧静止补时分支；
3. 任何动态覆盖缺口都会阻止最终合成；
4. 角色、场景和镜头连续性质量检查有可追踪结果；
5. 所有远程任务和本地渲染可从断点恢复；
6. 旧素材与旧成片未被覆盖；
7. 最终音频、字幕和视频时间轴误差不超过 0.25 秒；
8. 横竖屏分别生成完整、可播放、带 BGM 和烧录字幕的最终视频。

## 10. 实施顺序

1. 固化并提交现有 H3 原生链、监控和断点恢复代码；
2. 实现微分镜数据模型、时间覆盖算法和版本化断点；
3. 实现旧片段迁移和候选素材审核；
4. 扩展客户端以支持首帧、尾帧及 FL2VA；
5. 实现角色/场景资产与镜头提示词生成；
6. 实现视频质量门禁和自动重试；
7. 重写渲染器，禁止静止补齐并验证逐帧覆盖；
8. 用短样本完成端到端测试；
9. 从竖屏旧素材开始补齐，再恢复横屏；
10. 完成最终合成与整片验收。
