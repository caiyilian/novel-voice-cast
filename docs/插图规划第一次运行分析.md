## 二、V2 vs V3 关键改进

| 维度 | V2（715 张版） | V3（702 张版，当前最佳） |
|------|---------------|------------------------|
| 上下文安全 | ❌ max prompt tokens ~89k | ✅ **max 24,791** |
| 生成方式 | 少量调用批量输出（高幻觉风险） | **251 次细粒度调用，每轮最多 6 张** |
| 工具暴露 | 全部 8 个工具（含 update/delete） | **移除 update/delete，append-only** |
| list_proposals | 返回完整 prompt，上下文膨胀 | **紧凑 review 表，不塞完整 prompt** |
| 去重 | 无 | **程序级近重复去重** |
| 非正文过滤 | 无 | **过滤"插图/终幕/后记"等标记** |
| 冗余循环 | chunk 21 有大量 list/delete 循环 | **无冗余循环** |

### V3 架构变化

1. **Chunk 缩小**：从 300 行→126 行，降低单次上下文压力
2. **Append-only 模式**：不再暴露 `update_proposal`/`delete_proposal` 给 LLM，避免陷入修编号循环
3. **单轮上限 6 张**：每次 propose_illustration 最多 6 个调用，防止一次性批量生成
4. **紧凑 review**：`list_proposals` 返回缩略表而非完整 prompt
5. **程序级去重**：合并行范围重叠的近似提案


## 五、结论

**V3 版可以作为当前最佳结果继续往后走。** 理由：

1. **稳定性**：252 次调用 0 错误，上下文控制在 25K tokens 以内
2. **密度**：702 张插图，93.8% 行覆盖率，密度达标
3. **质量**：prompt 充分、角色基本齐全、无空描述
4. **架构**：append-only + 小 chunk + 紧凑 review，结构性问题已消除

### 剩余小问题

- 3 组同 range 轻微重复
- 14 组高重叠候选（但占比低，可接受）
- 5 张缺角色名（空镜，非错误）
- 个别 visual prompt 依赖视觉记忆而非角色卡（角色卡需后续补外观字段）

### 下一步建议

1. **抽 30-50 张做人工视觉一致性检查** — 看角色长相是否跨场景一致
2. **小规模生图测试** — 选几张 prompt 调 PuLID/Agnes API，看 prompt 到图的实际稳定性
3. **补充角色卡外观字段** — 当前角色卡缺视觉描述，导致 LLM 依赖视觉记忆推断角色长相
